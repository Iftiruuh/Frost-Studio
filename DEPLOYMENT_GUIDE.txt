FROST STUDIO — BEGINNER DEPLOYMENT GUIDE
=======================================

Goal:
Make the Frost Studio website available online so customers can submit orders,
and keep submitted orders/reference images saved between deployments.

YOU NEED
--------
1. A GitHub account.
2. A Railway account.
3. This project folder.
4. A private ADMIN_KEY that only the business owner knows.

PART A — PUT THE WEBSITE ON GITHUB
----------------------------------
1. Download and unzip frost-studio-railway-ready.zip.
2. Sign in to GitHub.
3. Create a new repository named:
   frost-studio
4. Set it to Private.
5. In the repository choose:
   Add file -> Upload files
6. Upload the CONTENTS of this folder so that package.json and server.js are
   visible at the top level of the repository.
7. Commit/upload the files.

IMPORTANT:
- Do not upload a .env file.
- The included .env.example is safe because it contains placeholders only.

PART B — DEPLOY ON RAILWAY
--------------------------
1. Sign in to Railway.
2. Create a New Project.
3. Choose Deploy from GitHub repo.
4. Connect GitHub if asked.
5. Select the frost-studio repository.
6. Wait for Railway to build/deploy it.

PART C — ADD THE PRIVATE OWNER KEY
----------------------------------
1. Open the Frost Studio service in Railway.
2. Open Variables.
3. Add:
   ADMIN_KEY = choose-a-long-private-secret
4. Add:
   STORAGE_ROOT = /app/storage

Example ADMIN_KEY:
FrostStudio-Owner-Only-Change-This-2026

Use your own key, not the example.

PART D — ADD PERSISTENT STORAGE
-------------------------------
This is important. Without persistent storage, orders/files may disappear after
a redeployment.

1. In the Railway project, create a Volume.
2. Attach it to the Frost Studio service.
3. Set the mount path exactly to:
   /app/storage
4. Railway will redeploy the service.

This one volume stores both:
- customer orders
- uploaded reference images

PART E — MAKE THE WEBSITE PUBLIC
--------------------------------
1. Open the Frost Studio service.
2. Go to Settings.
3. Find Networking -> Public Networking.
4. Click Generate Domain.
5. Railway will give you a public address similar to:
   something.up.railway.app

Open that address on your phone and computer.

PART F — TEST IT
----------------
Customer test:
1. Open the public website.
2. Add Chocolate Cake to the order.
3. Choose quantity.
4. Enter test customer details.
5. Select Pickup.
6. Submit the order.
7. You should receive an order number beginning with FS-.

Owner test:
1. Add /admin.html to the end of the website address.
   Example:
   https://YOUR-RAILWAY-DOMAIN/admin.html
2. Enter the same ADMIN_KEY you created in Railway.
3. Click Load Orders.
4. Confirm the test order appears.

PART G — FACEBOOK
-----------------
After you create the Frost Studio Facebook page:
1. Copy the Facebook page link.
2. Send it to ChatGPT.
3. The placeholder Facebook buttons can be connected to the real page.

PART H — BKASH
--------------
Do not activate live bKash yet unless Frost Studio has an official bKash
Merchant/API setup.

Never ask a customer for:
- bKash PIN
- OTP
- account password

When merchant credentials are ready, connect the official hosted bKash checkout.

PART I — CUSTOM DOMAIN (OPTIONAL)
---------------------------------
You do NOT need to buy a domain on day one.

Start with the Railway-provided address.

Later you can buy a domain such as:
froststudiobd.com
or another available name, and connect it to Railway.

BACKUP
------
Periodically back up your stored order data and uploaded reference images,
especially before major website changes.

FILES
-----
public/index.html  = customer website
public/admin.html  = private owner order dashboard
server.js          = order-saving server
data/orders.json   = local-development order data
uploads/           = local-development uploaded reference images
.env.example       = environment-variable example
package.json       = Node.js app configuration
